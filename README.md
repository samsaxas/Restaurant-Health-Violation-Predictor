# Restaurant Health Violation Risk Predictor

Predicts whether a NYC restaurant's **next inspection** will be high-risk (score >= 28, the grade-C range),
using only what is known from its *previous* inspections, then turns each prediction into a short
plain-English hazard report with an LLM (Gemini via LangChain).

> **Status of the results below:** the pipeline has been run end-to-end and unit-tested on a
> *synthetic* dataset. The real NYC DOHMH run is a single command (see "Reproduce") and fills the
> "Results on real data" block automatically. Nothing in the synthetic block describes real-world performance.

## Problem
NYC inspectors cannot visit every restaurant at once. A model that ranks restaurants by the chance of a
high-risk inspection helps prioritise visits. Missing a truly risky restaurant (false negative) costs more than
an extra visit (false positive), so **recall** and **PR-AUC** matter more than accuracy on this imbalanced target.

## Data
[DOHMH New York City Restaurant Inspection Results](https://data.cityofnewyork.us/Health/DOHMH-New-York-City-Restaurant-Inspection-Results/43nn-pn8j)
(NYC Open Data). One raw row = one violation. See `data/README.md` for download steps.

## Approach
1. **Clean and aggregate:** drop the `01/01/1900` placeholder dates and rows without a score; collapse violation rows to one row per (restaurant, inspection date).
2. **Target:** `high_risk = 1` if the inspection score >= 28.
3. **Leakage-safe features:** every feature comes from *earlier* inspections of the same restaurant (previous score, previous violation and critical counts, historical mean/max score, past high-risk rate, days since last visit, number of past inspections), plus borough, cuisine and inspection type. Unit tests check that the current inspection never leaks into its own features.
4. **Chronological split:** train on the earliest 80% of inspections, test on the most recent 20%.
5. **Imbalance:** SMOTE on the training data only (uses `imbalanced-learn` if installed, otherwise a built-in fallback; the backend used is recorded in the results).
6. **Models:** Logistic Regression + SMOTE (baseline), **Random Forest + SMOTE (main)**, and Random Forest with `class_weight` and no SMOTE (ablation).
7. **Metrics:** precision, recall, F1, ROC-AUC, PR-AUC, confusion matrix, all on the held-out future inspections.
8. **LLM hazard report:** the model predicts, the LLM only explains. Without `GEMINI_API_KEY` a deterministic template report is used.

## Reproduce
```bash
pip install -r requirements.txt

# 1. real data (download the CSV first, see data/README.md)
python -m src.train --data data/DOHMH_New_York_City_Restaurant_Inspection_Results.csv --label "NYC DOHMH (real data)"
python scripts/update_readme.py --block real --metrics results/metrics.json

# optional: LLM hazard reports
export GEMINI_API_KEY=...        # optional: GEMINI_MODEL=gemini-2.5-flash

# tests
pytest -q
```
Smoke test without the real data: `python -m src.make_synthetic` then `python -m src.train --data data/synthetic_inspections.csv --out results/synthetic`.

## Verification done so far
- 6 unit tests (history features exclude the current inspection, cleaning, chronological split, SMOTE, probability output, report fallback) pass. They were run with a simple Python runner in an environment without `pytest`, so run `pytest -q` once locally.
- Full training + evaluation run completed on synthetic data using the built-in SMOTE fallback. Not yet run with `imbalanced-learn`, on the real dataset, or with a live Gemini key.

## Limitations
- Predicts the *next* inspection from history, so restaurants with no previous inspection are not scored.
- Inspection type is known when a visit is scheduled, but re-inspections follow bad scores, so it correlates with history.
- SMOTE on one-hot features creates fractional category values; the no-SMOTE ablation is included for comparison.
- Threshold fixed at 0.5; a production system would tune it to inspector capacity.

## Project structure
```
src/data.py            load, clean, leakage-safe features, chronological split
src/smote.py           SMOTE (imbalanced-learn or fallback)
src/model.py           preprocessing + SMOTE + classifier wrapper
src/train.py           train, evaluate, save metrics/figures/sample reports
src/report.py          Gemini (LangChain) or template hazard report
src/make_synthetic.py  synthetic data in the DOHMH schema (testing only)
scripts/update_readme.py  writes results/metrics.json into this README
tests/test_pipeline.py unit tests
```
